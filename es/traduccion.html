¿Cómo funciona el sistema de traducción de Apps Bíblicas?

Para que cualquier persona pueda traducir o mejorar los textos de la suite sin necesidad de conocimientos de programación, hemos desacoplado todos los textos, títulos, descripciones y datos históricos en archivos independientes. Al traducir, únicamente se edita el texto en su idioma, preservando intacta la lógica técnica de cada aplicación.

¿Cómo traducir una aplicación de la suite?

El proceso está diseñado para ser directo y sin fricción. No necesitas instalar programas complejos ni compilar código si no lo deseas.

1

Arquitectura Descentralizada por App

Cada aplicación de la suite es completamente independiente y autónoma. Las traducciones residen dentro de cada app en su carpeta apps/{app}/locales/:

  • apps/medidas/locales/ — Pesas, medidas y monedas bíblicas
  • apps/atlas/locales/ — Lugares bíblicos, rutas y 12 tribus
  • apps/cronologia/locales/ — Cronología, reyes, profetas y eras
2

Elige la App y el Idioma

Cada carpeta locales/ contiene el archivo base es.json, traducciones existentes (ej. ru.json) y una plantilla _template.json con sus INSTRUCCIONES.md:

  • Modo JSON: Edita directamente el archivo del idioma correspondiente en la app elegida.
  • Autonomía total: Puedes traducir una app individualmente sin necesidad de tocar las demás.
3

Consulta wol.jw.org

Regla de oro: Nunca traduzcas literalmente nombres bíblicos propios, medidas antiguas ni libros canónicos.

  • Comprueba siempre la voz en *Perspicacia para comprender las Escrituras* en tu idioma en wol.jw.org.
  • Usa la Traducción del Nuevo Mundo oficial de tu idioma.
4

Carga Dinámica en index.html

Al añadir o actualizar un idioma:

  • El archivo index.html de cada app consume dinámicamente su JSON de ../locales/{lang}.json.
  • Los estilos visuales están 100% desacoplados en archivos .css independientes.
  • Compatibilidad universal garantizada tanto en servidores web como en protocolo file:// sin conexión.
¿Deseas traducir a un nuevo idioma (ej. Francés, Alemán, Portugués)? Solicita el paquete de traducción base o genera la carpeta ejecutando npm run i18n:new -- --lang=xx --name="Tu Idioma".

Directrices de Investigación y Fuentes Bíblicas

La suite Apps Bíblicas exige el más alto nivel de fidelidad histórica y textual. Todo dato o término debe fundamentarse exclusivamente en la biblioteca oficial wol.jw.org.

Prohibición Estricta: Fuentes Seculares Especulativas Queda totalmente prohibido utilizar Wikipedia, diccionarios laicos, foros o traducciones automáticas generales para términos bíblicos o cronología. Cada término debe verificarse en Perspicacia en el idioma de destino.
Categoría Fuente Obligatoria (wol.jw.org) Instrucción para el Traductor
Topónimos y Geografía (Atlas) Perspicacia (it-1 / it-2) y folleto «Veamos la buena tierra» Buscar el nombre del lugar bíblico en el tomo correspondiente. Utilizar la ortografía canónica de la Traducción del Nuevo Mundo en su idioma (ej. Susa, Meguidó, Hebrón).
Pesas, Medidas y Monedas (Medidas) Perspicacia, artículo «Pesas y medidas» Las equivalencias métricas son universales (codo = ~44,5 cm; bato = ~22 l), pero el nombre de la unidad debe concordar con Perspicacia en su idioma (ej. español: Codo; ruso: Локоть; inglés: Cubit).
Cronología y Personajes (Cronología) Perspicacia, artículos «Cronología», «Reyes», «Profeta» Mantener con precisión las fechas a.e.c. / e.c. señaladas en Perspicacia (Creación 4026 a.e.c., Diluvio 2370 a.e.c., Éxodo 1513 a.e.c., Desolación de Jerusalén 607 a.e.c., etc.).
Manuscritos y Códices (Historia) Perspicacia y libro «Toda Escritura es inspirada» Utilizar la denominación tradicional establecida (ej. Códice Sinaítico, Alejandrino, Papiro Chester Beatty).
Consejo práctico de búsqueda en wol.jw.org: Si buscas un término en tu idioma, escribe en la barra de búsqueda de WOL: it-1 [termino] o it-2 [termino]. Eso te llevará directamente al artículo enciclopédico oficial.

Estructura del Archivo de Traducción (JSON)

Cada fichero contiene pares de datos organizados para facilitar la tarea al traductor y proveerle el contexto necesario.

JSON 
{
  "_meta": {
    "language": "ru",
    "language_name": "Русский",
    "app": "medidas"
  },
  "ui": {
    "app_title": {
      "source": "Conversor de Pesas, Medidas y Monedas Bíblicas",
      "translation": "Конвертер библейских мер, весов и монет",
      "context": "Título principal H1 de la aplicación"
    },
    "reset_button": {
      "source": "Restablecer",
      "translation": "Сбросить",
      "context": "Botón de acción en la calculadora (máx. 16 caracteres)"
    }
  },
  "data": {
    "units": {
      "codo": {
        "name": {
          "source": "Codo",
          "translation": "Локоть",
          "context": "Unidad de longitud. Perspicacia it-1 voz 'Codo'"
        },
        "description": {
          "source": "Distancia desde el codo hasta el dedo medio (~44,5 cm).",
          "translation": "Расстояние от локтя до конца среднего пальца (~44,5 см).",
          "context": "Definición canónica de Perspicacia"
        }
      }
    }
  }
}

Reglas Importantes al Escribir la Traducción

1. Solo edita "translation"

No modifiques las claves (como "app_title"), ni el campo "source", ni el campo "context". Si modificas las claves, el sistema no podrá enlazar el texto en la aplicación.

2. Conserva las etiquetas HTML

Si el texto original contiene etiquetas como <strong>, <em> o <br>, debes mantenerlas en la misma posición semántica en tu traducción:

Fuente: <strong>100%</strong> fuentes verificadas
Traducción: <strong>100%</strong> проверенные источники

3. Respeta los marcadores dinámicos

Si una frase contiene variables entre llaves como {count} o {unit}, déjalas exactamente igual:

Fuente: Equivale a {value} metros
Traducción: Эквивалентно {value} метрам

4. Caracteres especiales y comillas

En formato JSON, si necesitas escribir comillas dobles dentro de una frase, debes escaparlas con una barra invertida: \"ejemplo\", o usar comillas angulares latinas («ejemplo») según las normas tipográficas de tu idioma.

Comandos de Automatización para Desarrolladores

Si trabajas en local clonando el repositorio con Node.js instalado, dispones de una suite de comandos automáticos en scripts/ para gestionar las traducciones sin esfuerzo:

Comando Descripción Ejemplo
npm run i18n:check Valida la integridad y sintaxis de todos los archivos JSON en cada aplicación (apps/*/locales/). npm run i18n:check
npm run i18n:new Genera la plantilla del nuevo idioma en todas las aplicaciones simultáneamente a partir de sus _template.json. npm run i18n:new -- --lang=fr --name="Français"
Cero dependencias en tiempo de ejecución: Los scripts de scripts/ utilizan exclusivamente APIs nativas de Node.js (sistema de archivos y utilidades JSON/CSV), manteniendo el repositorio limpio, ligero y libre de dependencias pesadas.
